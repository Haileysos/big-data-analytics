# 분산 시스템 Distributed Systems 의 4가지 핵심 메커니즘   
1. 데이터 파티셔닝 (Partitioning) [scale-out]   
   단일 노드 용량을 초과하는 대규모 데이터를 작게 쪼개어 여러 노드에 분산 저장한다.   
   이를 통해 물리적 저장 한계를 극복하고 수평적 확장을 가능하게 한다.  
2. 데이터 복제 (Replication) [fault tolerance]   
   장애 대비를 위해 동일한 데이터를 여러 노드(기본3개)에 중복 저장한다.   
   특정 노드가 고장나더라도 다른 노드의 복제본을 통해 데이터 유실없이 서비스를 지속한다.   
3. 병렬 처리 (Parallel Processing) [performance]   
   분할된 데이터 블록을 각 노드가 동시에 처리한다.   
   순차 처리 대비 전체 작업 시간을 노드 수에 비례해 획기적으로 단축시킨다.   
4. 조정 & 동기화 (Coordination) [Consistency]   
   마스터 노드가 전체 작업 할당, 진행 상황 추적, 장애 노드 감지, 결과 통합을 중앙에서 제어하여 분산 환경의 일관성을 유지한다.    
왜 분산 시스템인가?
- 단일 서버의 물리적 한계를 넘어선 수평적 확장(Scale-out) 전략
수직적 확장 Scale-Up
* 물리적 한계 : CPU 속도, 메모리 용량 등 하드웨어 발전 속도의 한계가 존재
* 비용 비효율 : 최고 사양 서버 비용은 성능 대비 기하급수적으로 증가
* 단일 장애점 : 서버 1대 장애 시 전체 서비스 중단 위험
수평적 확장 Scale-Out
* 선형적 확장성 : 필요한 만큼 저가 서버를 추가하여 성능 증대
* 비용 효율성 : 가성비 좋은 범용 장비 사용으로 TCO 절감
* 장애 허용성 : 일부 노드 장애에도 서비스 지속 가능


HDFS 핵심 특징 및 메커니즘
###### 앞서 배운 '분산 시스템의 4가지 핵심 메커니즘'이라는 설계도를 가지고 실제로 만든 프로그램이 바로 HDFS
1. 블록 기반 저장 (Block Storage)
   파일을 고정 크기(128/256MB)로 분할해 노드에 균등 분산 저장 병렬 처리의 기본 단위가 됨
2. 복제 정책 (Replication Policy)
   데이터 유실 방지를 위해 기본 3개 복제본 유지. NameNode가 장애를 자동 감지하고 복구 수행
3. 랙 인지 (Rack Awareness)
   물리적 Rack 구조를 고려해 복제본 배치. 전원/스위치 장애 시에도 데이터 보호 및 트래픽 최적화
4. WORM (Write-Once-Read-Many)
   한 번 쓰여진 데이터는 수정 불가. 데이터 일관성 단순화 및 높은 처리량 보장
